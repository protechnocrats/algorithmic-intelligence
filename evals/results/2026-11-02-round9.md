# Round 9: java-clinic with J11-J13 in pairs, Haiku and Opus, 2026-11-02

- **Agent:** Claude Code headless, one session at a time. 5 pairs on Haiku 5.5, then 3 pairs on Opus 5.5. Each pair has one session with the skill and one without, on the report flow (report, "apply all", decline every approval request).
- **Skill:** `evals/full-grading` at `d4acf87`. The skill files are the same as on `main`; the branch adds only harness changes and cases. Installed from a snapshot. With-skill sessions also had the README's recommended `CLAUDE.md` line.
- **Fixture:** java-clinic with the three new cases: J11, a comparison that must keep its uniform timing; J12, a grouped knapsack (NP-hard, pseudo-polynomial); J13, 3SUM counting (a conjectured quadratic bound, `int` overflow).
- **Cost cap:** $19 on reported session cost. **Spent: $24.97, $5.97 over the cap.** The cap only stopped new sessions from starting. The last Opus skill session started with $1.28 left, and each of its turns could still spend $5, so it cost $7.26. Its baseline was then skipped, which leaves Opus pair 3 without a baseline. Fixed in this branch: `run-pilot.sh` now lowers each turn's `--max-budget-usd` to what is left of the cap.
- **Grading:** `evals/grade.py` on every category. The judged rows are not filled yet (see "Judge").
- **Permissions:** the wider allowed-command list, without `--skip-permissions`, because the run was on a developer machine.

## Validity

**10 of 15 sessions are valid.** Four sessions had 10% or more of their tool calls refused. A fifth (haiku-5 skill) had all 4 of its shell commands refused, so it never ran the tests. It stopped without applying anything and said why, which is what the skill asks for, but the session cannot be scored. `grade.py` now marks a session invalid when more than half of its shell commands were refused, since the 10% gate missed this one; round 8's validity is unchanged by the new gate. Most refusals were `bash /tmp/<script>.sh`. Allowing that is the same as allowing any command, so the list is not widened further. **Next rounds should run in the dev container with `--skip-permissions`.**

**Every valid Haiku baseline changed a public signature.** `Ledger.rangeTotals(double[], ...)` became `rangeTotals(long[] amountsCents, ...)`, to make prefix sums exact. Every caller breaks, and amounts that are not whole cents can no longer be passed. This is case J8's floating-point trap, met by changing the contract rather than keeping it. One of the two invalid Haiku baselines did the same. The probe cannot compile against the changed signature, so these sessions have no other case results.

**Haiku with the skill flagged the same item and left it alone.** haiku-2: "B10 (prefix sums in the ledger): not applied. It changes rounding."

**The hostile-input trap again:** the one Haiku baseline whose code compiled (haiku-3, invalid on refusals) made J9 3.9 times slower under attack: 2.7 s to 10.4 s on colliding keys. Round 7 found the same pattern. No skill session did this.

**The new cases:**
- J12 and J13 were fixed with results unchanged in every session where the probe could run.
- J11 kept its uniform timing in every session.
- Neither J12 nor J13 separates the conditions: Opus without the skill solved both, and so did Haiku with it.

**Where the skill held back a speedup:** 3 of 4 Haiku skill sessions left J1's 2,000 round trips as they were. They listed batching as a behavior change: haiku-4 built it, and its differential test found that a failure of the single-patient call now surfaces differently (9 of 400 cases). The answer key's Pass line asks for the batched version, so these count as speedups held back, the same pattern as RB1 and RB2 in round 8. Whether haiku-4's difference matters depends on whether the single-patient call can fail while the batch call works, which the documented contract does not say. Opus with the skill batched it in both valid sessions.

## Cost

With the skill, Haiku cost 2.8 times the baseline ($0.88 against $0.31), and Opus 3.1 times ($5.85 against $1.91). Opus skill sessions also took 40 minutes against 6. That is the price of differential tests, planted-difference checks, and the report.

## Limits

- Small samples, and Opus has one valid baseline. Do not read the Opus columns as a result.
- The judge is partly blinded (`evals/GRADING.md`), and several judged checks ask for practices the skill teaches, so a baseline scores low on them by construction (see round 8, "Caution on the judged rows").
- 5 of 15 sessions invalid, all from permission refusals.

## Judge

Judge: `claude-sonnet-5-5`, 10 valid sessions, $2.11 against a $2 cap. The $0.11 overshoot came from a $0.50 floor on each judge call's budget; `grade.py` now starts a judge call only when $0.25 or more is left, and gives it only what is left. The judge scored the write-mode case JW1 as failed on every session although this round ran report mode only; `grade.py` now scores write-mode cases only on write sessions, and the scorecard below is regraded from the cached verdicts.

**What the judged rows add:**
- **Haiku baselines:** besides the signature change (J8, failed in 3 of 3), every valid Haiku baseline kept a hash map keyed by attacker-supplied records in J9 (failed in 3 of 3), the trap that cost 3.9 times under attack in haiku-3. They batched J1 correctly in 3 of 3, which Haiku with the skill did in 1 of 4.
- **Haiku with the skill:** passed J8, J12, and J13 in 4 of 4 and J9 in 2 of 4 (the other 2 kept the original scan for uploads with a null entry, so a quadratic path remains there). Failed J1 in 3 of 4: held back as a behavior change.
- **Opus with the skill:** passed every report case except J3 (partial in both sessions) in 2 of 2, including J6 and J7, where the baseline was partial: it named NP-hardness without a source and verified the wrap-around only on random minutes.
- **Protocol:** behavior changes held for review: skill 4 of 4 (Haiku) and 2 of 2 (Opus); baseline 0 of 3 and 0 of 1. Bugs reported: 3 of 3 and 2 of 2 with the skill, 0 of 1 and 0 of 0 without.
- **Declined behavior changes, version that keeps the behavior applied:** Haiku 0 of 4, Opus 1 of 2. This round's skill already had round 8's instruction for this, so for Haiku it is not working yet.
- **End-to-end share:** Haiku with the skill 1 of 4, Opus 2 of 2.
