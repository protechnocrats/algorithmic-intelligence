# Round 5: before-and-after cost tests, 2026-11-01

Three cost-reduction ideas, each tested against a "before" that differs in that one thing only. All sessions: Claude Code headless, Haiku 5.5, `java-clinic` report flow (report, "apply all", decline every approval), with the skill and the recommended `CLAUDE.md` loading line, one session at a time. Total cost **$4.68** against a $7 cap; every session valid (no stalls, no usage-limit errors).

| Test | Change | Before | After |
|---|---|---|---|
| A | Skill changes 1 and 2: work in few, large steps (batch independent tool calls, one harness for the whole run, short output), and write less (state each fact once, short final summary) | Round 4: 3 sessions, skill `a571b10` | 2 sessions, skill snapshot `round5-cost/skill-A` |
| B | Lower effort: `claude --effort medium` (less hidden thinking) | Test A | 2 sessions, same skill as A |
| C | Apply each approved item in its own sub-agent | Test A | 2 sessions, skill A plus the sub-agent instruction, sub-agent tool allowed |

**Quality bar, set before the runs:** no probe difference; case score no more than one case lower per session; no regression in the workflow checks (planted differences, verification levels, behavior changes held for review, every report section kept, report mode not changing source).

## Findings

1. **Noise is about $0.20 per session.** Test C's agents never used a sub-agent (the tool was offered and allowed, and the instruction was in the installed `WORKFLOW.md`; Haiku ignored it). So A and C ran the same skill in practice, and their costs ($0.93 to $0.94 against $0.64 to $0.88) show how much two identical setups vary. With two sessions per side, only differences well above that are real.
2. **Changes 1 and 2 kept quality and improved the workflow, but did not cut cost.** Same cost as round 4 ($0.94 against $0.95), sessions about twice as fast, fewer API calls (48 against 55 to 66), cheaper harness work ($0.28 against $0.35), no report overwrite, and the end-to-end share reported for the first time (2 of 2). The saving went into longer reports: report writing rose to 27% of the cost (about 55,000 output tokens). Kept in the skill.
3. **Medium effort cut cost by about a third and kept the code correct, but the reports got worse.** $0.65 against $0.94, beyond the noise. Code: identical results. Reports: one of two skipped the report file and the standalone review section, neither reported the end-to-end share, one planted fewer differences. The thinking that medium effort removes is partly what fills the report with the developer's evidence. **Use:** medium effort is fine for eval sweeps that grade code correctness with the probe; keep the default effort when the report itself is being graded. Not recommended to users as a default yet: two sessions are too few, and the report losses are the kind users rely on.
4. **Sub-agent apply was not tested.** Haiku ignored the instruction, so this round says nothing about its effect. The variant (`round5-cost/skill-C`) is not in the skill. Testing it needs a model that follows it, or a stronger instruction placed where the apply turn reads it.
5. **Report length is now the main cost lever left in the skill's control.** "State each fact once" and the short final summary did not shorten the reports. A concrete limit for straightforward items (for example the compact format as a hard maximum, or a length target per field) is the next thing to try, with the same before-and-after design.

## Harness changes used in this round

`run-pilot.sh` gained `--max-total-usd` (stop starting sessions past a total), a stall watchdog (`--stall-seconds`, default 600: stops only the stuck turn, marks the session invalid, skips its later turns), sessions that survive a stopped neighbor (the batch no longer ends), `--effort`, `--skill-src` (test a skill variant from a directory without committing it), and `--allow-subagents`. All were tested with stub agents before the run, and the cap and watchdog were active throughout it.
