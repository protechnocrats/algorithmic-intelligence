# Trigger test results: description rewrite and project instructions, 2026-10-31

Does the agent load the skill for a request? Prompts from `evals/trigger-prompts.tsv` (S: existing-code performance, W: new code over collections, N: trivial), run in fresh copies of ts-shop with read-only tools (`evals/trigger-test.sh`). Change tested: the description now leads with "Use it before writing new code that loops over collections or data (...)" instead of ending with "Also use when writing new code that ...". Same length class (920 characters), no other change.

Scoped line: `Use the complexity-optimizer skill when writing new code that loops over collections or data, and for any question about the speed or complexity of existing code.`

## Findings

1. **The description rewrite is safe but not a measurable improvement.** Opus loads the skill about as often as before, with no false loads; Haiku's gain (2 against 1, 3 against 2) is within noise.
2. **Haiku rarely loads skills from descriptions at all,** even for direct performance requests (3 of 12). Wording cannot fix that.
3. **A project-instruction line fixes it,** if it is scoped. The line the README used to recommend ("when writing new code") also loaded the skill for trivial helpers (`formatCents` 3 of 3) and did nothing for existing-code requests. The scoped line got 58 of 60 right (W 22/24, S 12/12, N 0/24). The README now recommends it.

## Limits

One fixture (ts-shop), 3 runs per prompt for Haiku and 1 to 2 for Opus. Instruction lines were tested on Haiku only.
